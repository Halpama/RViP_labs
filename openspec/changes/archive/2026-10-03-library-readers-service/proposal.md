# Proposal

## Why

Библиотеке нужен единый асинхронный REST-сервис для учёта читателей, состояния читательских билетов и выданных книг. Сейчас в репозитории нет реализации этого варианта, поэтому требуется заложить работающий API, устойчивую схему PostgreSQL и воспроизводимый Docker-запуск с миграциями.

## What Changes

- Добавить FastAPI-приложение читательского сервиса на Python 3.13 с асинхронным SQLAlchemy 2.x и `asyncpg`.
- Ввести единственную таблицу `readers` с уникальным номером билета, признаком активности билета, необязательной выданной книгой и датой регистрации.
- Реализовать CRUD-операции читателей и операции жизненного цикла билета и книги: изъятие билета, выдача и возврат книги.
- Добавить отчёт `GET /reports/summary` с общим числом читателей и числом читателей с книгой на руках.
- Добавить Alembic async-миграцию; приложение не должно создавать таблицы через `create_all`.
- Добавить Dockerfile, Docker Compose с PostgreSQL, healthcheck, одноразовым сервисом миграций и API на порту 3001.
- Добавить конфигурацию окружения, зависимости и краткий README с Docker- и локальным запуском, адресами и Swagger.

## Capabilities

### New Capabilities

- `library-readers`: Управление читателями библиотеки, билетами, выданными книгами и сводным отчётом через REST API.

### Modified Capabilities

- Нет.

## Impact

- Новые файлы в `apps/reader-service/`: приложение FastAPI, модели, схемы, роутеры, конфигурация БД, Alembic и зависимости.
- Новые корневые файлы `docker-compose.yml`, `.env.example`, `.gitignore` и обновление `README.md`.
- Новый PostgreSQL-сервис и миграционный процесс; публичный API доступен на `http://localhost:3001` и `/docs`.
