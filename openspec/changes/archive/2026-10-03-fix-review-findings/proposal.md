# Proposal

## Why

Ревью выявило расхождения между заявленным контрактом сервиса читателей и реализацией: PATCH позволяет менять состояние билета, часть проверок и сценариев не закреплена тестами, а воспроизводимость окружения и инструкции запуска недостаточно строгие. Нужно исправить эти замечания без изменения бизнес-схемы БД (одна таблица `readers`) и существующих маршрутов.

## What Changes

- Ограничить `PATCH /readers/{id}` профилем читателя: `full_name` и `card_number` не принимают `null` или пустые строки, пустое тело `{}` отклоняется HTTP 422, `card_active` и `book_title` недоступны для обновления, лишние поля отклоняются HTTP 422.
- Расширить API- и database-тесты для неизвестных идентификаторов, конфликтов, пустых списков, сводки и валидации PATCH; исправить тест после rollback так, чтобы он не обращался к протухшему ORM-объекту.
- Не добавлять тесты конкурентности и явно зафиксировать их как вне объёма.
- Закрепить точные версии Python-зависимостей и образов Docker.
- Дополнить README инструкциями запуска для Windows, macOS и Linux.
- Добавить `docs/ai-process.md` с ключевыми промптами, пересмотренными решениями и результатами проверок.
- Синхронизировать `AGENTS.md` и `.github/copilot-instructions.md` с правилами PATCH и обязательным запуском тестов без skipped.

- Публичные маршруты и таблица `readers` сохраняются; меняется только строгое поведение валидации PATCH и покрытие уже требуемых ответов.
